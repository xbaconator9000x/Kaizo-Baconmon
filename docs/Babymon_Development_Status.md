# Babymon implementation status

This branch implements experimental ROM data generation. It is not a playable, validated Babymon release. The live release must not be replaced by this branch until the remaining gameplay work passes validation.

## Implemented

- Reproducible Generation III manifest covering all 386 National Dex species: 126 Tier 1, 46 Tier 2, 161 Tier 3, 53 excluded. Source commit and input hashes are recorded in `public-patcher/babymon_sources.json`.
- Manifest parser fixes for multiline species records, the `SPECIES_NONE` initializer and unused Unown enum entries. Charmander, omitted from the handwritten list, is included.
- Seed-consistent Tier 1 starters and Tier 1 → Tier 2 → Tier 3 destinations written into actual FireRed Rev 1 ROM data after UPR randomization. All six starter script references are updated, including repeat references used for the rival choice.
- Seeded starter picks are passed into UPR before randomization, so its rival-team and starter-description code uses those picks. A separate Babymon bridge method leaves the other engine entry point unchanged.
- Each species retains its source evolution conditions. Trade items use item evolution codes. Nincada uses an ordinary level trigger and its extra-party evolution branch is removed.
- Source layout validation rejects modified evolution tables, unexpected starter data, wrong revisions and copier headers. The writer operates on a copy and does not mutate its input.
- All final and excluded species have empty evolution records. Stats, abilities and learnsets are left as generated by UPR.
- Batch output includes a spoiler evolution-map file and explicitly experimental metadata. Experimental runs are not score eligible and record patch selections/settings as custom overrides.
- Run-profile code and markup recovered from the generated index into the build sources, so rebuilding retains existing profiles.

The writer checks cover 100 seeds, all tier boundaries, terminal records, internal species ID conversion, deterministic output, BST decreases, rejection of invalid layout data and unchanged input buffers. Controlled seeds 88262 and 6759 produce Caterpie → Kakuna → Dragonite and Slowpoke → Scyther → Beedrill, respectively. The latter encodes direct-use Metal Coat, in accordance with the final specification.

Batch checks exercise the generated page handler and ZIP pipeline, including the experimental Babymon branch. The Java engine is stubbed in these checks. Binary writer tests use synthetic layout fixtures, not a commercial game image or emulator execution.

The existing `test.cjs` and `test_selection.cjs` cannot run here because their clean FireRed Rev 1 fixture is absent. These are blocked checks, not passes.

2. Verify starter-description and rival-team output in a real generated ROM; the early Java integration and custom-starter indices now pass engine-boundary checks.

5. Enforce permanent runner identity, no pivots, permadeath, permitted healing moves, TM provenance/compatibility/legality and successful-relearn payment. Restrict Sketch relearning.

8. Rebuild and publish the live patcher only after all release gates pass.

The implementation source is authoritative; the unchanged root index remains the previous live release during this work.

## Evolution implementation follow-up

`public-patcher/evolution/` now contains executable native C evolution logic and a guarded source installer for the Celadon trade attendant, direct-use trade items, a persistent lab Day/Night terminal, evolution-item shop stock and cross-generation animation checks. Its host-native test suite passes all 183 eligible species-method branches and source installation checks. See that directory's README for exact behavior and test commands.

This completes the source-level implementation of those services, not their binary deployment. A clean FireRed Rev 1 test ROM, verified original/native symbols, target ARM build and emulator validation remain missing here. The previously generated batch ROMs do not yet contain these services. Beauty access and the separate gameplay restrictions remain outstanding.

## Optional binary evolution beta

The patcher now includes an Evolution support (beta) checkbox and compiled Thumb payload. Ordinary patching and randomiser bases both install it. The native payload passes 183 branch executions in Unicorn; full patcher installation and idempotence pass on the supplied Rev 1 Baconmon image. A real Kaizo Java randomisation preserves the native reservation and species-specific evolution methods. The reserved clock variable is now 0x40D0; 0x40F2 conflicted with the existing engine.

Full gameplay validation, Feebas Beauty access, removal of starter viability safeguards and remaining Babymon restrictions/scoring are still unfinished. Earlier statements about absent binary payloads are superseded by this update.

## Attempt guard follow-up

The development patcher now installs a Babymon-only permanent-runner, single-party and permadeath guard, including saved terminal status and a result screen. The Babymon batch path requires evolution configuration and checks the native guard after Java output. Targeted mGBA tests and actual evolution-under-guard checks passed; normal-mode patch output remains byte-identical. This supersedes the absent-guard portions of the earlier backlog, but not the TM/relearner, blind starter, viability safeguard, scoring or release gates. See [Babymon attempt guard](Babymon_Attempt_Guard.md) for exact behavior, validation and remaining work.

The earlier evolution-only beta also passed targeted mGBA checks for Day/Night Eevee, cartridge-save clock persistence, Celadon trade consent, every trade-item type, ordinary Fire Stone, wrong-item rejection and the actual randomised starter trio. These targeted tests supersede the statement that all in-game evolution validation is outstanding; they do not establish a completed playthrough.
